  - **Why:** the first real `trace_pcap` from the server (2026-11-03, a clean call, 52% digital zero) showed two faults of mode `audx`:
    - the first word of the call was cut 13–18 dB: a −61 dBFS click set the AGC level, the gain rose to +23 dB and the model got +14 dBFS peaks;
    - soft onsets right after a pause were cut 12–37 dB by the model itself (AGC gain 0 dB there).
    Design and offline measurements: `docs/audx-stateful-design.md` section 9.
  - **New keys** (`audio_preprocessing.audx.*`, env `AUDIO_PREPROCESSING_AUDX_*`). Code defaults keep the old behaviour; the shipped yaml and the three ConfigMaps carry the chosen values (in the ConfigMaps they only act with `MODEL=audx`):
    - `agc_ceiling_dbfs` (`_AGC_CEILING_DBFS`), yaml −16, default 0 = off: the AGC never lifts the block it is applied to above the ceiling. The gain drops at once at the start of that block (or part of a block within one `step()`); rising stays ramped. Must lie between `agc_target_dbfs` and 0.
    - `clamp_to_input` (`_CLAMP_TO_INPUT`), yaml true, default false: no output bin above the input bin (input = after the AGC).
    - `max_attenuation_db` (`_MAX_ATTENUATION_DB`), yaml 12, default 0 = no limit: no output bin cut by more than this.
    The clamp sits after the network, before the inverse STFT, in both `step()` and the whole-signal call, so the two still agree. The "AudX ready" log line prints the ceiling and the clamp.
  - **Tried and dropped:** dither (1/3/10 LSB) in the digital-zero runs before the model did not change the cut onsets: the model cuts onsets after any pause, not only after digital zero.
  - **`probe_audx.py`:** `--agc-ceiling-dbfs`, `--clamp-to-input`, `--max-attenuation-db` (default off, like the code).

- `src/nemotron_testbed/trace_pcap.py` (new), `scripts/trace_pcap_to_wav.py` (new), `tests/test_trace_pcap.py` (new, 23 tests), `src/nemotron_testbed/{config,coordinator,metrics,logging_config,client_pcap}.py`, `scripts/client_wav.py`, `etc/nemotron-engine.yaml`, the 3 ConfigMaps, `tests/{test_config_yaml,test_client_pcap}.py`, `docs/{trace-pcap-design (new),scripts-guide (0, 2.1, 2.3)}.md`: `trace_pcap` writes, per stream, a pcap of the audio the engine received and of the audio after AudX, to listen whether AudX helps on real calls.
  - **Why:** user request; design agreed in `docs/trace-pcap-design.md`.
  - **Switch:** `trace_pcap.enabled` (env `TRACE_PCAP_ENABLED`), default off, restart needed; every stream. Off creates no tracer, no thread and no file. Limits: `max_streams` (0 = all), `max_seconds` per stream (0 = none), `min_free_mb` (5120; below it no new file and the open ones are closed).
  - **File:** `logs/pcap/<YYYYmmdd-HHMMSS>_<session>_<stream>_<rpc>.pcap`; a synthetic SIP INVITE whose SDP declares `L16/16000` (Wireshark needs it for the dynamic payload type), then RTP PT 96, L16 big-endian, 20 ms packets.
    - `in` (port 40000): the chunk as the gateway sent it, before chunk_seq / RTP policy, so chunks the engine drops are in it; timestamps = `rtp_timestamp` moved to a 16 kHz clock.
    - `audx` (port 40002): what VAD/ASR get (AudX output, the flush of the last D, raw audio after an AudX failure), carrying the timestamps and capture times of the matching `in` content, so the 244 ms AudX delay is compensated and gaps line up.
    - Marker on the first packet of each chunk / each AudX output, so tools rebuild the chunks.
  - **Engine:** the event loop converts and queues (measured ~124 µs per 80 ms chunk); one `trace-pcap` thread writes. A full queue, a write error, a low disk or `max_seconds` stops only that trace (`TRACE_PCAP_STOPPED`), never the call. Logs `TRACE_PCAP_ENABLED / OPEN / SKIPPED / STOPPED / CLOSE` (CLOSE carries the AudX region counts); metrics `trace_pcap_streams_active`, `trace_pcap_streams_total{outcome}`, `trace_pcap_bytes_total`. `logging_config.py` gained the new log fields (the JSON formatter only prints listed fields).
  - **Tools:** `trace_pcap_to_wav.py` writes lined-up `*_in.wav` / `*_audx.wav`. `client_pcap` reads the SDP of a capture (L16 flows, `a=label`), `client_wav.py --pcap <trace> --flow in|audx` replays the chunks as recorded (8 kHz timestamps again); `--jitter` / `--chunk-ms` / `--gw-resampler` do not apply and are reported.
  - **Review fixes (2026-11-03, a test reproduces each):** a stopped trace no longer keeps adding to its AudX segment table (~7 MB/hour per stream on a long call); a close that overtook a queued "open" (full queue) no longer leaves that file open; replay of a chunk older than the first one goes back in time instead of jumping ~2^31 ticks. Unused code removed (`StreamTrace.path`, `wall_clock`, `counted_active`, a dead branch in `trace_pcap_to_wav.py`).
  - **Verified:** pytest 961 passed, 19 skipped. tshark 4.6.9 lists both flows as L16 (test runs when tshark is installed). Mutations (no D compensation, no held / flush write, no `in` write, no 20 ms grid) each fail tests. Not yet run on the server; RTP Player playback to be confirmed by ear.

- `src/nemotron_testbed/client_pcap.py`, `src/nemotron_testbed/client_audio.py`, `scripts/client_wav.py`, `tests/fixtures/rtpgw_golden.json` (regenerated), `tests/test_client_pcap.py`, `tests/test_client_wav.py`, `README.md`, `docs/scripts-guide.md (2.1, probe_vad, 8)`: the rtpgw emulation follows the gateway's new audio path.
  - **Why:** rtpgw (working tree on `b0a434b`, uncommitted on 2026-11-02) now upsamples 8 -> 16 kHz with a half-band FIR by default (`audio.resampler: sinc`, `linear` kept for A/B) and decodes PCMU with ITU polarity. The engine itself needs no change: its timeline stays continuous because rtpgw subtracts the filter delay from `rtp_timestamp`. The user asked to update the test tools.
  - **What changed:**
    - PCMU decode uses ITU polarity (wire `0x00` -> -32124). `to_narrowband` output now follows the input sign instead of being negated.
    - New `GatewayResampler(mode)`: `sinc` is a port of `resampler.go` (103 taps, Kaiser beta 7.86, state across packets, 26-sample delay = 3.25 ms, `flush()` returns the 52-sample tail); `linear` is the old `upsample_2x`.
    - `build_chunks(resampler=...)`: chunk timestamp = packet timestamp minus the delay, and the filter tail goes through the chunker before its remainder, like `audio_pipeline.go` / `pcap_replay`.
    - `to_narrowband(audio, resampler="sinc")`: same length as the input, delayed by 52 samples with sinc; the tail is dropped because the live gateway never delivers it.
    - `client_wav.py --gw-resampler sinc|linear` (default `sinc`) for both `--pcap` and `--narrowband`. Other scripts that call `to_narrowband` (`probe_vad`, `client_dual_wav`, `kaggle/eval_wer`, `kaggle/enhance_wavs`) get `sinc`.
  - **Golden fixture:** produced by a Go harness compiled from copies of rtpgw `resampler.go`, `chunker.go`, `pcm.go` and `g711.go` (sha256 in `provenance`); the old inputs are kept, every chunker case runs with both resamplers, and 9 sinc resampler cases plus the 26 taps are new. The Python taps match Go bit for bit.
  - **Measurements are not comparable across the change:** VAD / WER numbers taken with `--narrowband` before 2026-11-02 used the linear path. On `vi_asr_0114` (notebook pipeline, pre_roll 250) the run without AudX now also loses the short "Vâng" at 31.26 s, which it kept with linear.
  - **Verified:** pytest 933 passed, 19 skipped. The notebook `notebook/noise_pipeline_kaggle.ipynb` (outside the repo) got the same port (`GW_RESAMPLER`) and still matches `EngineCoordinator` in all 3 variants.

## 0.3.22

- `coordinator.py` (`_apply_rtp_policy`): jitter-corrected path no longer updates `expected_rtp_timestamp` or `last_source_rate` — a packet arriving slightly behind expected (within `rtp_jitter_tolerance_ms`) had its trailing-edge timestamp used to advance `expected_rtp_timestamp` backward, causing the next in-order packet to appear as a forward gap and trigger spurious silence insertion; mirrors the same fix applied to the OOO accept path in v0.3.14.
- `translation_runtime.py` (`_run`): replaced blocking `_jobs.get()` with `_jobs.get(timeout=5.0)` loop that exits on `_shutdown_requested`; `shutdown()` now sets `_shutdown_requested` before enqueuing the sentinel — previously if the shutdown sentinel failed to enter a full queue, the worker thread blocked indefinitely and `shutdown()` never returned within its timeout.
- `coordinator.py` (`_handle_runtime_result`): `translate_emit_source_partials` path now guards against emitting when `source_language` is still `"auto"` — if the ASR model has not yet detected the language, the partial was emitted with `language="auto"` which is meaningless to translation clients; partials for the translate task are suppressed until the language is resolved.
- `translation_runtime.py` (`_decode`): replaced `startswith` prefix check with `re.sub(r'(?i)^{lang}\s*:\s*', '')` — the model occasionally outputs `"en : text"` (spaces around the colon) which the exact-length `startswith` + `[len(prefix):]` strip left as `" text"` with a leading space; the regex handles all spacing variants.
- `translation_runtime.py` (`_process_batch`): `TRANSLATION_LATENCY` is now observed once per job (`elapsed / len(batch)`) instead of once per batch — batched jobs were counted as a single observation, understating job count and overstating per-job latency in histograms.
- `coordinator.py` (`_handle_tts_result`): removed `TTS_JOBS.inc()` from the phrase-chain continuation path — subsequent phrases of a multi-phrase utterance were each incrementing the counter, inflating `TTS_JOBS` by `len(phrases) - 1` relative to the number of utterances synthesised.
- `coordinator.py` (`_process_audio`): `VAD_SPEECH_AUDIO_SECONDS` is no longer incremented on the `VadEvent.END` boundary chunk — the END chunk contains trailing silence that triggered the VAD decision; counting it inflated the speech audio metric with silence duration.

- `config.py` (`Settings.from_env`): added validation for `TTS_EN_CONFIG_PATH` and `TTS_VI_CONFIG_PATH` when `TTS_BACKEND=piper` — catches missing config JSON at startup instead of at first synthesis.
- `config.py` (`Settings.from_env`): added `TRANSLATION_COMPUTE_TYPE` validation against the set of types accepted by CTranslate2 — invalid values now raise at startup.
- `config.py` (`Settings.from_env`): added log-level validation for `LOG_LEVEL`, `CONSOLE_LOG_LEVEL`, and `THIRD_PARTY_LOG_LEVEL` — typos raise `ValueError` in `Settings` rather than in `configure_logging`.
- `config.py` (`Settings.from_env`): extracted `ASR_DEVICE`, `TRANSLATION_DEVICE`, and `TTS_DEVICE` to local variables — eliminates duplicate `os.getenv` reads for each device pair.
- `main.py` (`serve`): `coordinator.start()` is now wrapped in `asyncio.wait_for(timeout=300 s)` — hangs during model loading now time out with a clear error.
- `main.py` (`serve`): `quiet_nemo_logging` and `quiet_transformers_logging` called after model load — suppresses Transformers/NeMo handlers installed during import.
- `main.py` (`configure_cpu_threads`): check `settings.asr_devices` instead of `settings.device` — correctly skips CPU thread config when all workers run on CUDA.
- `main.py` (`serve`): bind failure now stops `stats_logger` and `gpu_monitor` before raising — no resource leak when gRPC address is unavailable.
- `main.py` (`serve`): shutdown order fixed: `server.stop(grace)` first, then `stats_logger.stop()` and `gpu_monitor.stop()`, then `coordinator.shutdown()` — stats capture covers the full RPC drain period.
- `logging_config.py` (`configure_logging`): old handlers are removed and closed before adding new ones — prevents file descriptor leak on repeated calls.
- `metrics.py` (`TTS_SYNTHESIS_RTF`): removed "Piper" from description — metric covers both Piper and Magpie backends.
- `gpu_monitor.py` (`GpuMonitor`): `pynvml.nvmlShutdown()` called in `stop()` via a shutdown closure stored at init — NVML context released on graceful shutdown.
- `stats_logger.py` (`_labeled_gauge`): composite key now joins all label values with `/` instead of taking only the first — future multi-label gauges will produce correct stats keys.

## 0.3.9

- `config.py`: `VAD_BACKEND` validated at startup — raises `ValueError` immediately instead of failing on the first RPC.
- `vad.py` (`SileroSpeechProbability`): added `threading.Lock` protecting `_pending` and `_last_score` — eliminates race between `score()` (executor thread) and `reset()` (event loop thread).
- `vad.py` (`SileroSpeechProbability`): Silero JIT model loaded once per `(path, device)` pair and `copy.deepcopy`'d per stream — avoids re-reading from disk for each new call while keeping LSTM states isolated per stream.

- `audio.py` (`resample`): non-`ImportError` exceptions from soxr now log a warning and fall back to linear resampler instead of propagating.
- `audio.py` (`_linear_resample`): added comment that no cross-chunk phase continuity is maintained — install soxr for production quality.
- `buffers.py` (`SampleBuffer.append`): added comment explaining why `.copy()` is intentional for buffer ownership.
- `vad.py` (`VadController.process`): added comment explaining `speech_candidate_ms` hard-reset design trade-off.
- `tests/test_g711.py`: added ITU-T G.711 correctness tests (silence values, `float32_to_pcm16` overflow prevention, audioop/LUT tolerance check).
- `tests/test_buffers.py`: added `prepend()` rollback tests, storage-ownership isolation test, underflow guard test.

## 0.3.8

## 0.3.7

- `TranslationRuntime._tokenize`: added `max_length=512, truncation=True` to `tokenizer.encode` — prevents unbounded token sequences on unusually long utterances.
- `TranslationRuntime._tokenize/_decode/_translate/_translate_many`: replaced `assert ... is None` guards with explicit `RuntimeError` raises that survive Python `-O` optimization.
- `TranslationRuntime._translate` / `_translate_many`: guard against CTranslate2 returning an empty hypotheses list — logs a warning and returns `""` instead of raising `IndexError`.

## 0.3.6

- `NemotronRuntime`: raw audio buffer trimmed after feature extraction — keeps CPU memory O(1) per stream instead of O(utterance length).
- `NemotronRuntime`: feature cache trimmed after each step to retain only the `pre_cache` lookback window — keeps GPU memory O(pre_cache + chunk_size) per stream instead of O(utterance length).

## 0.3.5

- G.711 encoding fallback replaced with numpy lookup-table vectorization — eliminates per-sample Python loop on Python 3.13+ where `audioop` was removed.
- `resample()` now logs the missing-soxr warning only once per process instead of once per TTS job.
- `MagpieTtsRuntime._synthesize` validates `do_tts` output tensor shapes before indexing; raises `RuntimeError` with dimensions in message instead of a cryptic `IndexError`.
- `_split_phrases` no longer splits at `,;:` — only `.!?` sentence boundaries are used, preventing unnatural mid-clause phrase breaks in Magpie (neural) TTS.
- Replaced two `assert self.tts_runtime is not None` guards in coordinator with explicit `RuntimeError` raises that survive Python `-O` optimization.
